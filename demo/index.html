Why this happens

Row by row

A tabular model scores each transaction on its own features — amount, hour, device type. A $34 charge at 2am on a burner card looks like a thousand other small legitimate charges. Nothing in that one row crosses the threshold, so it clears.

Node by node

The GNN treats the card, address, email domain and device fields as edges instead of features, exactly as this repo's graph construction does. Message passing lets each transaction borrow risk from its neighbors — eight quiet transactions plus one loud shared device add up to a network score that clears the fraud threshold together.

Node layout mirrors the graph construction in gnn_fraud_detection.py: nodes are transactions, edges are shared card1–6 / addr1–2 / email domain / device fields, and groups sharing a value connect through a star topology once the group passes twenty members — as described in the README.
